# 프로젝트 작업 원칙

## 기술 기준선

- Java 17
- Spring Boot 3.x 최신 안정 버전인 3.5.16
- Gradle 8.14.3 Wrapper
- Spring Web MVC, Spring Data JPA, Bean Validation, Actuator
- H2 Database, Flyway
- JUnit 5 기반 테스트
- Lombok (보일러플레이트 코드 제거 목적)

Spring Boot 전체 최신 버전이 아닌, 최초 프로젝트 조건인 Spring Boot 3.x 범위의 최신 안정 버전을 사용한다.

## 코딩 컨벤션

### Lombok 사용 정책

프로젝트 전반에서 보일러플레이트 코드 제거를 위해 Lombok을 표준으로 사용한다.

| 어노테이션 | 사용 대상 | 비고 |
| --- | --- | --- |
| `@Getter` | 모든 엔티티, DTO, 이벤트 클래스 | Setter는 사용하지 않고 도메인 메서드로 상태 변경 |
| `@NoArgsConstructor(access = AccessLevel.PROTECTED)` | JPA 엔티티 | JPA 프록시 생성을 위해 필수, 외부 직접 생성 방지 |
| `@Builder` | DTO, 이벤트 클래스 | 빌더 패턴으로 명시적 객체 생성 |
| `@RequiredArgsConstructor` | Service, Component 등 Spring Bean | 생성자 의존성 주입 (`@Autowired` 미사용) |
| `@Slf4j` | Service, Controller, 스케줄러 등 | 로깅 (일반 Application Log) |
| `@ToString` | DTO, 이벤트 클래스 (선택) | 엔티티에는 지연 로딩 필드가 포함될 수 있으므로 사용 지양 |

**사용 금지 사항**:
- `@Data` — 엔티티에 사용 금지 (`equals`/`hashCode` 오동작 및 순환 참조 위험)
- `@Setter` — 엔티티의 상태 변경은 도메인 메서드를 통해서만 수행
- `@AllArgsConstructor` (엔티티) — JPA 스펙과 충돌 가능성

### 코드 주석 정책

- 클래스에는 협업자가 책임과 사용 목적을 빠르게 이해할 수 있는 간단한 설명을 작성한다.
- 메서드에는 수행 기능과 중요한 상태 전이·검증 제약을 간결하게 설명한다.
- 코드만으로 명확한 문법, 필드명 또는 구현 절차를 그대로 반복하는 주석은 작성하지 않는다.
- 공개 API와 도메인 메서드는 Javadoc을 우선 사용하고, 내부 구현 주석은 의사결정 배경이 필요한 경우에만 작성한다.

## Git 작업 원칙
- 사용자 소유의 기존 변경 사항을 임의로 제거하거나 덮어쓰지 않는다.

## 문서화 원칙

요구사항과 아키텍처가 확정되기 전까지의 질의응답을 단순 대화로만 남기지 않고 다음 산출물에 반영한다.

1. PM 관점의 요구사항 정의서
   - 프로젝트 목적과 범위
   - 사용자 및 외부 시스템 정의
   - 기능·비기능 요구사항
   - 정책, 예외 상황 및 인수 조건
   - 미결정 사항과 결정 이력
2. 아키텍처 설계서
   - 시스템 컨텍스트와 책임 경계
   - 결제 및 지갑 원장 모델
   - 외부 PG 연동 방식
   - 멱등성, 장애 복구 및 대사 전략
   - 보안, 관측 가능성 및 테스트 전략
3. 아키텍처 결정 기록(ADR)
   - 선택한 방안
   - 선택 근거
   - 검토한 대안
   - 트레이드오프와 후속 영향

문서는 요구사항 논의가 진행됨에 따라 지속적으로 갱신하되, 확정된 내용과 가정 또는 미결정 내용을 구분한다.
