# 프로젝트 작업 원칙

## 기술 기준선

- Java 17
- Spring Boot 3.x 최신 안정 버전인 3.5.16
- Gradle 8.14.3 Wrapper
- Spring Web MVC, Spring Data JPA, Bean Validation, Actuator
- H2 Database, Flyway
- JUnit 5 기반 테스트

Spring Boot 전체 최신 버전이 아닌, 최초 프로젝트 조건인 Spring Boot 3.x 범위의 최신 안정 버전을 사용한다.

## Git 작업 원칙

- 프로젝트 생성 결과의 최초 커밋 메시지는 `init`으로 한다.
- agent는 커밋을 생성하지 않으며, 사용자가 자신의 GitHub 계정과 Git 작성자 정보로 직접 커밋한다.
- agent는 원격 저장소에 푸시하지 않는다.
- 사용자 소유의 기존 변경 사항을 임의로 제거하거나 덮어쓰지 않는다.

## 문서화 원칙

요구사항과 아키텍처가 확정되기 전까지의 질의응답을 단순 대화로만 남기지 않고 다음 산출물에 반영한다.

1. PM 관점의 요구사항 정의서
   - 프로젝트 목적과 범위
   - 사용자 및 외부 시스템 정의
   - 기능·비기능 요구사항
   - 정책, 예외 상황 및 인수 조건
   - 미결정 사항과 결정 이력
2. 아키텍처 설계서
   - 시스템 컨텍스트와 책임 경계
   - 결제 및 지갑 원장 모델
   - 외부 PG 연동 방식
   - 멱등성, 장애 복구 및 대사 전략
   - 보안, 관측 가능성 및 테스트 전략
3. 아키텍처 결정 기록(ADR)
   - 선택한 방안
   - 선택 근거
   - 검토한 대안
   - 트레이드오프와 후속 영향

문서는 요구사항 논의가 진행됨에 따라 지속적으로 갱신하되, 확정된 내용과 가정 또는 미결정 내용을 구분한다.
