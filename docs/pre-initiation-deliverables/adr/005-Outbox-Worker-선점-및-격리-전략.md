# ADR-005: Outbox Worker 선점 및 격리 전략

## 상태

승인 및 구현

## 결정

Outbox 처리는 API와 독립 배포되는 `outbox-worker`가 소유한다. 여러 인스턴스는 DB 조건부 갱신으로 이벤트 임대를 획득하며, 임대 소유자만 PG 후속 처리를 수행한다. 실패 이벤트는 지수 backoff 후 재시도하고 한도 초과 시 삭제하지 않고 `DEAD_LETTER`로 격리한다.

## 이유

- API 장애가 후속 처리 스케줄을 중단시키지 않는다.
- 별도 분산 잠금 제품 없이 Outbox 원장에서 선점 결과를 추적할 수 있다.
- 임대 만료로 Worker 비정상 종료 후 처리를 복구할 수 있다.
- 격리 원장을 보존하여 장애 분석과 향후 수동 재발행 승인에 활용할 수 있다.

## 트레이드오프

- DB가 공통 장애 지점으로 남는다.
- PG 호출 완료와 내부 상태 반영 사이의 종료 구간에는 재호출 가능성이 있어 PG 멱등 처리가 필수다.
- 네이티브 조건부 갱신 쿼리는 운영 DB 전환 시 방언과 잠금 특성을 다시 검증해야 한다.
- `DEAD_LETTER` 자동 재발행과 삭제는 이번 범위에서 제공하지 않는다.
