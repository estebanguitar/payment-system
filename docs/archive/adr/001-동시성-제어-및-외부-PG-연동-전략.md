# ADR 0001: 동시성 제어 방식 및 외부 PG 연동/암호화 전략 선택

- **상태**: 승인됨 (Accepted)
- **날짜**: 2026-08-08
- **작성자**: PM / Architect / Tech Lead

---

## 1. 맥락 (Context)

결제 시스템 구축 시 다수의 요청이 동시에 들어올 때 지갑 잔액의 정합성을 유지해야 하며, 가상 외부 PG 연동 시 외부 승인/취소 결과 처리 및 민감 외부 응답 데이터의 안전한 관리가 요구된다.

---

## 2. 의사결정 (Decisions)

### 2.1 지갑 동시성 제어: 비관적 락 (Pessimistic Lock)
- **선택**: `Pessimistic Lock (SELECT ... FOR UPDATE)`
- **이유**:
  - 결제/충전/환불 처리는 정확한 잔액 계산과 경합 방지가 최우선임.
  - 충돌 가능성이 있는 동일 고객의 잔액 수정 시 낙관적 락(Optimistic Lock) 재시도 로직보다 DB 레벨의 비관적 락이 확실하게 초과 차감 및 음수 잔액을 방지하고 트랜잭션의 예측 가능성을 높임.

### 2.2 가상 외부 PG Client Component
- **선택**: Spring Bean 기반의 가상 외부 PG Client Component 구현
- **이유**:
  - 테스트 및 데모 시 외부 HTTP 서버 의존성 없이도 승인(`APPROVED`), 거절(`FAILED`), 시스템 에러(`ERROR`), 타임아웃(Timeout) 시나리오를 안정적으로 시뮬레이션할 수 있음.
  - 가상 결제 결과를 결정론적으로 제어할 수 있는 테스트 헬퍼 및 헤더/파라미터 스위치 제공.

### 2.3 외부 응답 원문 암호화 (AES-256-GCM)
- **선택**: 애플리케이션 수준 `AES/GCM/NoPadding` 암호화 저장
- **이유**:
  - 요구사항 `EXT-002`에 따라 외부 API 응답 원문을 로그 테이블에 안전하게 저장해야 함.
  - 12바이트 무작위 IV와 128비트 인증 태그로 기밀성과 위변조 탐지를 함께 제공함.
  - 암호화 키는 Base64로 인코딩된 32바이트 값만 허용하고 `PAYMENT_ENCRYPTION_SECRET` 환경 변수로 분리 주입하여 소스코드 및 DB 덤프 노출 시에도 데이터 안전성 확보.
  - 암호문은 `v1:{Base64(IV)}:{Base64(ciphertext+tag)}` 형식으로 저장하여 포맷 버전을 식별함.

---

## 3. 결과 및 영향 (Consequences)

- **긍정적 영향**:
  - 비관적 락으로 인해 잔액 정합성이 엄격하게 보장됨.
  - 외부 PG 연동의 다양한 예외 케이스(타임아웃, 거절 등)에 대해 완벽한 테스트 코드 작성 가능.
  - 보안 요구사항 만족.
- **트레이드 오프**:
  - 동일 계정에 매우 높은 초당 동시 요청이 몰릴 경우 DB 락 대기 시간이 발생할 수 있으나, 단일 고객 잔액 수정의 범주이므로 비즈니스 정합성이 우선임.
