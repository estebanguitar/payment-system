# Outbox Worker 분리 구현 결과

## 1. 목적과 승인 범위

`ARC-001`~`ARC-003`에 따라 API 프로세스에서 Outbox 스케줄링을 제거하고, PG 승인·취소 후속 처리와 고립 이벤트 복구를 독립 Gradle 모듈 및 실행 프로세스로 분리한다. 삭제 API와 원장 자동 보정은 범위에서 제외한다.

## 2. 코드 수준 변경

- `outbox-worker` 모듈에 독립 실행 진입점과 전용 설정을 둔다.
- 실행 가능 이벤트를 조회한 뒤 짧은 별도 트랜잭션의 조건부 갱신으로 선점한다.
- `payment_outbox`에 Worker 임대와 다음 시도 시각을 추가하고 `PROCESSING`, `DEAD_LETTER` 상태를 도입한다.
- 실패 시 지수 backoff를 적용하고 한도 도달 이벤트를 삭제 없이 격리한다.
- 임대가 만료된 이벤트는 다른 Worker가 다시 선점한다.
- Actuator와 Micrometer로 heartbeat, 성공·실패·재시도, 대기·격리 건수를 제공한다.

## 3. 정합성 전략

DB 조건부 갱신 결과가 1건인 Worker만 외부 처리를 시작한다. 임대는 강제 종료 시 영구 고착을 막는다. PG 호출 직후 프로세스가 종료되는 구간에는 재호출 가능성이 있으므로 PG 멱등키를 유지하며, 업무상 유효 처리를 한 번으로 수렴시킨다.

## 4. 검증

- API Controller 없이 Worker Context가 기동되는지 검증한다.
- 같은 이벤트에 대한 두 번째 Worker 선점이 실패하는지 DB 통합 테스트로 검증한다.
- 선점 성공 이벤트만 복구 UseCase로 전달되는지 단위 테스트로 검증한다.
- 실패 횟수 한도 도달 시 독립 트랜잭션에서 `DEAD_LETTER`로 전환되고, 포이즌 이벤트 뒤의 후보도 계속 처리되는지 검증한다.
- API 컨텍스트에 실제 `@Scheduled` 메서드가 존재하지 않는지 검증한다.
- API와 Worker 테스트, JaCoCo HTML, `bootJar`를 검증한다.

## 5. 운영 제약

API와 Worker는 반드시 같은 외부 공유 DB를 사용해야 한다. 파일 기반 H2는 로컬 개발 확인 용도이며, 다중 서버 운영에서는 공유 RDBMS와 해당 DB 방언에 맞춘 선점 쿼리를 검증해야 한다.
